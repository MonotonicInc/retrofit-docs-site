# docs.retrofit.sh

The site that publishes [retrofit](https://github.com/MonotonicHQ/retrofit)'s
documentation.

This repository holds the theme, layouts and configuration only. Every page
the site renders is generated by retrofit: the prose docs, the navigation,
the command reference captured from retrofit's own `--help`, and the
reference tables. To change what a page says, edit it in retrofit. No docs
content is committed here.

## Stack

- **Hugo**, version pinned in `netlify.toml` (the same pin as retrofit.sh).
- **hugo-book**, a Hugo module pinned in `go.mod`. Hugo fetches it with Go.
- **Netlify** for hosting.

## Develop

Needs Hugo, Go, and a retrofit checkout (default `../retrofit`):

```sh
make build                    # write the docs tree from retrofit, then build into public/
make serve                    # the same tree, served at http://localhost:1313
make build RETROFIT=~/src/retrofit
make check                    # build, then check the rendered navigation against the manifest
```

That is one docs tree, served at the root. The published site is built from
releases:

```sh
make versions                 # what versions.toml publishes, from releases on GitHub
make fixture                  # pack this retrofit checkout's tree as a release under _fixtures/
make versions RELEASES_DIR=_fixtures
make versions-test            # the versions/ tests; they run Hugo
```

`make tree` runs `go run ./cmd/docs -out _tree` in the retrofit checkout.
`hugo.toml` mounts `_tree/content` as the content directory and
`_tree/manifest.json` as `data/manifest.json`. `_tree/` is ignored.

The build fails if a page the manifest names has no page in the build, or if
a link between docs names a page the tree does not have. `make check` adds
`scripts/check-nav`: on every page, the navigation lists every manifest page
in order under its section, every entry resolves, and the page's own entry is
the one marked active.

## Versions

`make versions` (the `versions/` Go module) builds the site Netlify
publishes. `publish` in `versions.toml` chooses the layout.

**Before 1.0, `publish = "current"`**, the setting today:

- `/current/` only, from the docs bundle (`retrofit_docs.tar.gz`) of the
  newest full release of any line on `MonotonicHQ/retrofit` (tags
  `bin-vX.Y.Z`, later `vX.Y.Z`, read from the repository's public git tags
  with no token and no API call; a draft has no tag). A new
  release publishes with no edit here. No `/X.Y/` path exists;
- until the first full release, the newest WIP pre-release
  (`bin-vX.Y.Z-wip.N`) instead, its version in the top bar and every page
  `noindex`. Once a full release exists WIPs are ignored, with no edit
  anywhere;
- every page is its own canonical, and the top bar names the version with
  no switcher;
- under every page, one sentence points at the release notes
  (`layouts/_partials/docs/inject/footer.html`); it drops out at 1.0.

**From 1.0, `publish = "lines"`** with `lines = ["1.0", ...]`:

- each listed line from its newest full release, at `/X.Y/`, and the newest
  line again at `/current/`;
- `/current/` is canonical on every page the newest line has
  (`layouts/_partials/canonical.html`);
- the version in the top bar opens the other lines, at the same page where
  it exists (`layouts/_partials/topbar.html`).

`/current/` exists under both, so links printed by 0.x binaries keep
resolving. Either way, each bundle is checked against its release's
`checksums.txt` and refused on a mismatch or a manifest naming another
version, and the root holds `_redirects` (`/` to `/current/`), `/fonts/`
(fonts.css loads the faces from the root) and `404.html`.

Every bundle is fetched and checked before anything is built, so a refusal
leaves no partial site. Until a release or WIP carries a bundle (retrofit
kata abgt), `make versions` refuses on the newest WIP's missing bundle; use
a fixture.

## Deploy

Netlify builds `main` with `make versions` (`netlify.toml`); a deploy
preview or branch deploy builds against its own host with every page
`noindex`. Nothing deploys by hand: retrofit's release workflow POSTs the
site's build hook after each publish (its `docs-site` job), and the build
fetches what `versions.toml` publishes. A rebuild from unchanged releases
writes byte-identical files, so Netlify uploads nothing new.

Set once, outside this repository:

- **Netlify site** from `MonotonicInc/retrofit-docs-site`, production
  branch `main`; build settings come from `netlify.toml`.
- **Domain**: `docs.retrofit.sh` added to the site, with Netlify's TLS
  certificate and HTTPS forced. DNS is at Porkbun, where `*.retrofit.sh`
  already points at Netlify; a `CNAME` from `docs` to the site's
  `<name>.netlify.app` is the explicit record.
- **Build hook**: Netlify's build hook for `main`, stored as the
  `DOCS_SITE_BUILD_HOOK` secret in `MonotonicInc/retrofit`'s `release`
  environment. Unset, a release's `docs-site` job warns and asks nothing.
- **Plausible**: `docs.retrofit.sh` as a Plausible site, its script URL as
  `plausibleScript` in `hugo.toml`. It loads only on the production deploy
  served at `docs.retrofit.sh` (`layouts/_partials/analytics.html`).

## Chrome

- **Top bar**: the lowercase name linking retrofit.sh, search, and the
  version from `manifest.json`.
- **Under the page**: previous and next, then, before 1.0, one sentence
  pointing at the release notes.
- **Left**: the manifest's sections in order, not hugo-book's file tree.
  Previous and next follow the same order.
- **Right**: the page's table of contents.
- **Off**: edit-this-page and last-change links, comments, the service
  worker. Light theme only; the design system has no dark mode.

## Style

retrofit-site's design system (`avw_retrofit-design-system.md` there) governs
how the site looks. Its `tokens.css`, `fonts.css`, fonts and favicon are
copied here verbatim and pinned in `style.lock`:

```sh
make style-check              # copies against style.lock, and against ../retrofit-site's HEAD if present
make style-sync               # re-copy from ../retrofit-site at HEAD (or REF=<commit>) and rewrite style.lock
```

Never edit a copy here; change it in retrofit-site, commit there, then
`make style-sync`. CI runs `make style-check`.

`assets/styles/custom.css` restyles hugo-book onto the tokens. tokens.css and
hugo-book both define `--space-1`, `--space-4` and `--space-8`, with different
values, so the build loads tokens.css with its scale renamed `--rf-space-N`
(`layouts/_partials/docs/inject/head.html`); the copy itself is unchanged.

## Layout

```
hugo.toml                     config: the theme import, the _tree mounts, hugo-book params
go.mod, go.sum                the hugo-book pin
Makefile                      tree, build, serve, check, style-*, versions, fixture, clean
netlify.toml                  Hugo pin, contexts, headers
style.lock                    the retrofit-site commit and SHA-256 of each copied file
versions.toml                 what the site publishes: /current/ only, or per line from 1.0
versions/                     the published build (Go, its own module): build and pack
scripts/check-nav             the rendered navigation against the manifest
scripts/style-sync            copy the design system files from retrofit-site
scripts/style-check           hold the copies to style.lock
assets/css/                   tokens.css, fonts.css (copies)
static/fonts/, favicon.svg    fonts, their licenses, the mark (copies)
assets/styles/custom.css      hugo-book's style hook: the restyle onto the tokens, top bar and pane layout
layouts/
  baseof.html                 hugo-book's, with the top bar, the manifest menu and a TOC-only right pane
  _partials/
    topbar.html               name, search, version, the version switcher
    nav.html                  the left navigation from manifest.json
    canonical.html            the canonical link: /current/ on a versioned build
    page-rel.html             a page's path under its version
    manifest-check.html       build guard: every manifest page renders
    docs/html-head.html       hugo-book's, with the canonical hook, paper theme-color, light only
    docs/prev-next.html       hugo-book's, in manifest order
    docs/html-head-favicon.html  hugo-book's, linking the mark only
    analytics.html            Plausible, on the live site only
    docs/inject/head.html     hugo-book hook: the guard, analytics, noindex on previews and WIPs, the design system CSS
    docs/inject/footer.html   hugo-book hook: the pre-1.0 note pointing at the release notes
```

`layouts/baseof.html`, `layouts/_partials/docs/html-head.html`,
`layouts/_partials/docs/prev-next.html` and
`layouts/_partials/docs/html-head-favicon.html` replace hugo-book's files of
the same name. When the pin moves, diff them against the
theme's copies.

To move the hugo-book pin:

```sh
hugo mod get github.com/alex-shpak/hugo-book@<commit>
```
